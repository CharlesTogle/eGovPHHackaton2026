1. The 4 Operational Layers (Barangay-Scoped)

Layer 1

Alert Ingestion

PAGASA / NDRRMC / PHIVOLCS push CAP v1.2 alerts via webhook. 9-digit PSGC maps each alert to specific Barangay records. AI auto-drafts official assessment questions.

State: DRAFT

INVARIANT: Zero citizen pushes

Layer 2

LGU Control Plane

Layer 2 is the HANDA service boundary. Barangay Portal, Developer Console APIs, and future LGU dashboards review, edit, publish, export, and monitor assessments here.

State: DRAFT → ACTIVE
Layer 3

Citizen Ping

High-priority push notifications + pop-up banners delivered inside eGovPH Super App. Targeting: Barangay PSGC + GPS geofence.

State: ACTIVE
Layer 4

Citizen Pong

30-second check-in: "Are you affected?" + needs selection. 1 response = 1 affected citizen record. Live Barangay dashboard, non-respondent list, CSV/PDF export.

State: VERIFIED

Phase 1 — Authorization Code Grant (Browser ↔ SSO)

1 User clicks "Login" → Browser redirects to eGovPH SSO login page
2 User authenticates (password, biometrics, 2FA) with eGovPH SSO
3 eGovPH SSO redirects back with an Authorization Code (single-use, short-lived)
4 Browser forwards the Auth Code to HANDA Backend (code only — no token yet)

Phase 2 — Server-to-Server Token Exchange (HANDA ↔ SSO · zero browser involvement)

5 HANDA Backend exchanges Auth Code for tokens via POST /token on eGovPH SSO (confidential client, server-side)
6 eGovPH SSO returns: access_token (15 min) + refresh_token (24h) + id_token (JWT with user claims)
7 HANDA validates JWT signature (against eGovPH JWKS), confirms identity, stores tokens in server-side session store

Phase 3 — Session Establishment (Browser ↔ HANDA · httpOnly cookie)

8 HANDA issues a session_id cookie to the browser: HttpOnly · Secure · SameSite=Lax · Path=/
9 Browser automatically sends Cookie: session_id=xyz... on every subsequent HANDA API call
10 HANDA resolves session → fetches server-side access_token → calls external APIs on user's behalf

Phase 4 — Silent Token Refresh (HANDA ↔ SSO · transparent to browser)

11 HANDA detects access_token expiry → uses stored refresh_token to get a new one from eGovPH SSO
12 If refresh fails (expired/revoked) → HANDA clears session → Browser redirects to SSO login (re-auth)
What the browser can see in the Network tab:
Only the opaque session_id cookie and the initial authorization code.
The actual access_token, refresh_token, and JWT id_token never touch the browser.
XSS can steal nothing. CSRF is blocked by SameSite + origin checks.
The browser is just a thin session client — HANDA is the real OAuth client.

Path A — Developer Console API (server-to-server, no browser)

▸ City backend gets API keys from developers.handa.gov.ph
▸ City backend calls Layer 2 APIs with X-HANDA-API-Key header
▸ No OAuth redirect flow needed — machine-to-machine trust
▸ HANDA validates API key against LGU registry → returns PSGC-scoped dashboard data
▸ Citizen push delivery and check-in writes stay internal to HANDA/eGovPH

5. System Roadmap & Future Expansions

Expansion 1

City-Wide Cascading Push

  • Parent-child multi-tenancy via city.handa.gov.ph
  • City mayors and CDRRMO get parent-tenant controls
  • "Publish City-Wide" cascades across child barangays
  • Barangay-level telemetry remains separate and preserved
Expansion 2

Verification API Gateway

  • External fintechs and community apps call GET /v1/verifications/citizen
  • Citizen logs into partner platform with eGovPH SSO
  • HANDA verifies active Layer 4 check-in status
  • Partners display an "eGov Verified Disaster Victim" trust badge
  • Anonymized beneficiary tokens preserve privacy under RA 10173
